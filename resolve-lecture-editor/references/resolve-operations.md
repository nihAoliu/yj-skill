# Resolve 接口与工程操作

## 当前能力与快照

使用 davinci_resolve MCP 状态、get_whats_new、search_scripting_api、get_scripting_api、get_scripting_docs。21.1是制作基线，实际 schema 优先。使用 GetSettings/SetSettings、GetProperties/SetProperties、ImportMedia([{FilePath:path}])，不要复制旧版重载写法。

run_script 预注入 resolve/project，只运行 Resolve API 逻辑，设置 result 返回可序列化数据；文件/网络/进程不在此沙箱执行。由宿主读取脚本正文、传入 MCP、保存返回 JSON。不仅为文件读写改用 unsafe 或修改脚本安全偏好。

只读快照脚本为 scripts/resolve_snapshot.py。向 MCP 传正文，不在普通 shell 中假装已有 resolve 对象。快照失败不得以空对象冒充成功。快照用于结构保护，未含全部效果/自动化状态，复杂工程按需补充。

## 原素材剪辑路径

不要虚构通用 SplitClip、任意片段 SetStart/SetEnd 或 ripple 区间接口。Timeline.DeleteClips 删除的是完整项目，不是任意时间段。只删除单条音轨再 ripple 可能破坏同步。

1. 首次开始剪辑且没有工作版本时，复制原时间线；已有剪辑工作版本则复用。锁定原版与当前工作版本身份，每次写入前核对目标。
2. 跨片段、字幕、变速、效果、复合片段的剪辑，只有用户允许 UI 时才可使用已验证的 Resolve 原生 UI 编辑命令；禁止 UI 时优先验证工程交换方案，无法保留则报告具体受阻项。先在测试副本验证选择、联动、轨道锁定和 ripple 范围，再从后往前删除并回读。通过实际可用 UI 工具执行，不能声称 MCP 已有对应命令。
3. 简单无特效的1×口播可按保留区间重建副本：仅当能完整保留源范围、各轨对齐、音量/变换/启用及关联属性时，清除副本受影响项目，以指定源范围和 recordFrame 重建。写前保存完整计划及恢复依据；不清媒体池。媒体源 fps 与 timeline fps 分开计算。
4. 重建无法保留字幕、Fusion、调色、转场等编辑时，不静默采用。可用 UI 或经验证的工程交换方案；缺少能力则报告具体受阻项，继续独立分析。用户不应为普通转写承担手工准备。
5. 测试帧端点约定：1帧、相邻两段、非零起始码、分数 fps。API 的 source endFrame 含末帧与否和内部半开区间分开处理，以 GetStart/GetEnd/GetDuration 回读确认，不只看 True。

剪辑可 ripple，必须同步全部相关内容；包装禁止 ripple。删除原始媒体、修改原版时间线不在范围内。

## 共同写入规则

- 以工程/时间线稳定 ID 确认目标，名称仅展示；用户切换活动时间线不能导致写错。
- 写前快照对比预计状态；日志保存操作编号、目标与实际返回 IDs。
- API 无通用 validateOnly 或批量事务保证。本地预检后分步执行，每步检查，失败先回读。
- 用户移动/修剪/调音/改字与记录不一致时，不自动恢复旧值。
- 包装比较忽略本技能已记录新增对象，但包括原对象源范围、位置、轨道、启用、音量等。复制后 IDs 可能变化，建立副本对应关系，不能直接比较两份 IDs。
- 仅回滚本技能拥有且未经用户另行修改的对象。不假定一个 Undo 撤销整个批次。

无成片自动导出、无默认渲染队列操作、无渲染设置改写。

## 本次实测的 AppendToTimeline 注意事项

在 Resolve 21.1、29.97 DF 源素材、30 fps 时间线上，省略 mediaType 的指定区间追加曾返回空；显式分别追加 video=1/audio=2、指定 trackIndex 和 recordFrame 后成功。分开追加后用 SetClipsLinked，并回读两轨范围与关联 ID。

该环境中 startFrame=300,endFrame=300 返回空；[300,301] 产生1帧，[301,330]产生29帧，[1000,2000]产生1001个时间线帧。不要沿用旧版“endFrame 必须减1”的假设，也不要将这组结果推广到所有帧率。写入后 GetSourceStartFrame 可能比请求小1帧；保留请求和实际映射，检查取整是否仍在预留气口内。

重建时复制 Inspector 属性、启用状态和音画关联；调色用原 TimelineItem.CopyGrades 到新视频条目。Fusion、复杂自动化或无法证明保留的属性仍应走其他经验证路径。

## 中英双语字幕区域

用户要求双语字幕时，建立一条字幕轨、两个原生字幕区域：R1中文、R2英文；默认中文显示在英文上方。每个区域独立编辑与设置样式，两种语言的对应条目保持同一入点与出点。不用单条字幕内中英换行替代区域，也不建立两个语言轨来替代。

先检查当前接口是否支持区域操作。Resolve 21.1本次实测没有公开的区域增改接口；可复用用户工程中已经存在的原生双区域结构，通过DRT交换在临时副本中验证；按下述版本管理规则更新当前工作版本，不能每次交换都累积一个长期版本。不要因此调用用户禁止的computer use。

已验证的DRT结构：`SubtitleTrackVec`内一个主`Sm2TiTrack`保存R1字幕；该轨`LayersVec/Element/Sm2TiTrack`保存R2字幕，子轨`BaseTrack`指向主轨DbId，两者`Sequence`指向目标序列。区域样式与层数来自真实原生模板，不猜测FieldsBlob等不透明字段。保留字幕以外的工程内容，并为新增对象分配独立ID；导入后再次导出验证。

`GetItemListInTrack('subtitle',1)`在本次实测仅返回基础区域，不能据其数量宣称双区域均已验证。必须检查导出DRT中的主区及子区，逐项核对中英文文字、数量、入点/时长、区域关联，再核对原音画与策划标记未变化。所有验证使用真实最新状态，不能用生成文件冒充导入后结果。

`ExportCurrentFrameAsStill`本次未包含字幕层；字幕数据回读通过不代表画面排版已验收。保留这一验证边界，由可用且获授权的预览方式检查字体、位置与行距。

## 时间线版本管理

- 保留原始时间线作为恢复依据。默认内容剪辑、包装各保留一个持续更新的工作版本；不为每次修改递增v编号或复制整条时间线。
- 恢复预告与告别、修改字幕文字/区域/样式、调整标记、调音量和局部剪辑等日常修订，直接在当前对应工作版本上执行。写前保存结构快照与修改记录，不能把创建新时间线当作普通备份的唯一方式。
- 只有大幅重剪、需要保留两种方案供比较、或验证可能影响工程结构的操作时，才建立额外副本。额外副本标明用途，验证结束后清理本次创建且未经用户修改的临时测试副本。
- DRT等交换方式可能必须导入为新时间线，这是接口限制，不是新增长期版本的理由。先验证导入结果；可安全回填时更新现有工作版本。只能以导入结果替代工作版本时，说明原因、核对用户最新修改、保存恢复文件并更新状态中的工作时间线ID；不要声称原地修改，也不要擅自删除旧的用户工作版本。
- 用户已保留的历史版本先保留；清理它们须有用户明确指示，不按版本号批量删除。阶段内名称保持稳定，只在有意保留多个方案时区分名称。
